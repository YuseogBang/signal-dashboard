# 투자 시그널 대시보드 — Portfolio Case Study

## 한 줄 소개

브로커 REST API에서 받은 시장 데이터를 서버 측 어댑터로 안전하게 가져와, 여러 기술적 지표를 설명 가능한 시그널과 위험관리 정보로 변환한 금융 데이터 분석 대시보드입니다. 현재 공개 데모에는 토스증권 캔들 API 어댑터가 연결되어 있고, NH선물 REST API는 동일한 어댑터 계약에 연결할 수 있도록 확장 지점을 분리했습니다.

## 문제 정의

RSI와 MACD만 단순히 평균내면 두 모멘텀 지표를 섞은 것 이상의 설명력이 약합니다. 그래서 이 프로젝트는 다음 질문을 화면에서 직접 확인할 수 있게 만드는 데 초점을 맞췄습니다.

- 지금 시장은 추세장인가, 횡보장인가?
- 현재 시그널은 실제 거래량으로 뒷받침되는가?
- 변동성을 감안하면 손절가와 포지션 크기는 어떻게 계산되는가?
- 과거 데이터에서 이 시그널을 따랐다면 단순 보유보다 나았는가?

## 구현한 분석 흐름

```text
브로커 REST API
        ↓
서버 측 API 어댑터
        ↓  인증 + 시세/호가/계좌 데이터 조회
정규화된 시계열 데이터
        ↓
RSI · MACD · ADX · SMA · 상대거래량 · ATR
        ↓
동적 가중치 시그널 · 리스크 가이드 · 백테스트
```

## 핵심 설계

### 1. 시장 상태에 따른 동적 가중치

ADX가 25 이상이면 추세가 뚜렷하다고 보고 MACD 비중을 65%로 높입니다. ADX가 20 미만이면 횡보 구간으로 보고 RSI 비중을 65%로 높입니다. 그 사이 구간은 50:50으로 둡니다.

이 비율을 숨기지 않고 대시보드에 노출해, 사용자가 “왜 이 시그널이 나왔는가?”를 확인할 수 있도록 했습니다.

### 2. 거래량은 점수와 분리된 확인 축

상대거래량은 최근 20일 평균 대비 당일 거래량으로 계산합니다. 방향성 시그널이 나왔을 때 상대거래량이 1.2배 이상이면 거래량 확인 배지를 표시합니다. 거래량을 점수에 억지로 합산하지 않고, 신호의 신뢰도를 판단하는 별도 정보로 분리했습니다.

### 3. ATR 기반 리스크 가이드

ATR을 사용해 시그널 방향에 따른 손절가와 목표가를 제안하고, 사용자가 입력한 계좌 규모와 거래당 리스크 비율을 바탕으로 권장 수량을 계산합니다. 입력값은 브라우저 안에서만 계산되며 서버로 전송하지 않습니다.

### 4. 단순하지만 검증 가능한 백테스트

BUY/STRONG_BUY에서 보유하고 SELL/STRONG_SELL에서 현금화하는 롱 온리 전략을 단순화해, 전략 누적수익률과 단순 보유 수익률을 비교합니다. MDD, 승률, 거래 횟수도 함께 표시합니다.

거래비용·슬리피지·유동성·과최적화는 반영하지 않았기 때문에 예측 모델이 아니라 분석 로직을 검증하는 참고용 도구로 명확히 표시했습니다.

## API 연동에서 보여주고 싶은 것

이 프로젝트에서 외부 금융 REST API는 계좌 거래 시스템을 완성했다고 과장하기 위한 것이 아니라, 브로커의 인증·시장 데이터를 실제 애플리케이션 분석 흐름에 연결하는 구현 경험을 보여주는 핵심 증거입니다.

- 서버에서 브로커 인증정보를 사용해 액세스 토큰 발급
- API 키·시크릿은 프론트엔드에 노출하지 않고 서버 환경변수로 관리
- 종목·주기·조회 건수 등 요청 파라미터 검증
- 공급자별 응답을 공통 OHLCV 스키마로 변환해 차트와 지표 계산에 사용
- API 실패 원인을 인증 오류·허용 IP·종목 없음·요청 한도로 구분해 사용자에게 표시

공개 데모에서는 샘플 데이터와 CSV 모드를 함께 제공하고, 허용된 환경에서는 실제 REST API 조회를 실행합니다. API 제공자별 인증·IP·모의거래 정책의 차이를 README와 화면에서 숨기지 않습니다.

## NH선물 REST API 확장 포인트

NH선물 공식 안내에 따르면 API 사용을 위해 HTS의 `2043 API 서비스 사용등록`, 모의거래 신청과 테스트 로그가 필요하고, 모의 테스트 완료 후 IT 담당자 승인으로 리얼 거래 전환이 진행됩니다. 따라서 NH선물 연동은 다음 어댑터 계약에 맞춰 연결합니다.

```text
MarketDataProvider
  ├─ getCandles(symbol, interval, count)
  ├─ getQuote(symbol)
  └─ normalize(response) -> { date, open, high, low, close, volume }
```

현재 저장소는 실제 NH 엔드포인트를 추측하지 않고, 공개 데모에서 검증 가능한 토스 캔들 어댑터와 공통 정규화·분석 계층을 분리해 두었습니다. NH선물 개발 문서와 모의 API 인증키를 받으면 이 계층의 공급자 어댑터만 교체해 시세·계좌·주문 API로 확장할 수 있습니다.

## 지원서에서 보여줄 데모 순서

1. 샘플 종목에서 종합 시그널과 ADX 기반 가중치가 함께 표시되는 화면을 보여줍니다.
2. 리스크 패널에 계좌 규모와 1회 리스크 비율을 입력해 ATR 기반 권장 수량을 확인합니다.
3. 백테스트 패널에서 전략과 단순 보유의 누적수익률·MDD·승률을 비교합니다.
4. CSV 업로드로 임의의 OHLCV 데이터를 분석할 수 있음을 보여줍니다.
5. 마지막으로 브로커 REST API의 인증·시세 조회 구조와 서버 측 프록시 코드를 설명합니다.

## 한계와 다음 단계

- 백테스트에 거래비용·슬리피지·분할매매가 아직 반영되지 않았습니다.
- 단일 종목·롱 온리 전략이므로 시장 전체 성과를 의미하지 않습니다.
- 공개 Vercel 데모는 브로커별 IP 허용 목록·모의거래 정책에 따라 샘플/CSV 모드가 필요할 수 있습니다.
- 다음 단계로는 고정 IP 프록시, 다중 종목 스크리닝, 파라미터 워크포워드 검증, 거래비용 반영을 고려할 수 있습니다.

## 사용 기술

React 19 · Vite · Recharts · PapaParse · Vercel Serverless Functions · Broker REST API adapter
